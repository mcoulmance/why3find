  version/tag.

## Bump version

- Replace `## Unreleased` by `## version - YYYY-MM-DD` in `CHANGES.md`.
- Bump version in `dune-project`.
- Run `make` and `make -C vscode version`.
- Check that the change was correctly propagated to
  `why3find.opam`, `VERSION` and `vscode/package.json`.
- Check the output of `dune exec -- why3find --version`.
- Commit the changes on release branch (or master).

- Create a new release on GitLab (Deploy/Releases) and the associated tag.
- Add a message to the created tag so that it is not a lightweight tag.
- This push started a new `tag` pipeline, run the  `vscode-extension` job in
  this pipeline to produce the `vscode/why3-platform-x.y.z.vsix`
- Browse the artefacts of the pipeline job, copy the URL of the produced
  artefact, and add it to the upcoming release page under name `VSCode
  Extension`, with Package kind.

## Add to opam

Releasing a package to opam amounts to get a PR merged on the
[opam-repository](https://github.com/ocaml/opam-repository). We will use the
[opam-publish](https://github.com/ocaml-opam/opam-publish) plug-in.

Prerequisites:
- A Github account
- A valid [Github token](https://github.com/settings/tokens)
  - Choose Classic token with scopes `public_repo` and `workflow`.
  - Keep the generated token (will not be accessible again).
- Having `opam-publish` installed.
  - Running `opam publish` should be sufficient to install the plug-in.

Opening the PR:
- Checkout release tag (detached mode is OK).
- Run `opam publish https://git.frama-c.com/pub/why3find/-/archive/$version/why3find-$version.tar.gz`, that is the source code link generated by the Gitlab release.
- Check and validate the informations presented by opam publish.

- Watch over the opam-repository CI and get the PR merged.

- Publish on Zulip and such
