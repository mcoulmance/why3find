## Bump version

- Replace `## Unreleased` by `## version - YYYY-MM-DD` in `CHANGES.md`.
- Bump version in `dune-project`
- Run `make` and `make -C vscode version`.
- Check that the change was correctly propagated to
  `why3find.opam`, `vscode/VERSION` and `vscode/package.json`.
- Check the output of `dune exec -- why3find --version`.
- Commit the changes on release branch (or master).

- Push and check that the CI pipeline for this commit succeed.

## Git Archive

- Create a new release on the GitLab and the associated tag
- Add a message to the created tag in prevision for future steps
- This push started a new `tag` pipeline, run the  `vscode-extension` job in
  this pipeline to produce the `vscode/why3-platform-x.y.z.vsix`
- Browse the artefacts of the pipeline job, copy the URL of the produced
  artefact, and add it to the upcoming release page under name `VSCode
  Extension`, with Package kind.

## Add to opam

- You need to have a Github account and to open a PR on
  [https://github.com/ocaml/opam-repository](opam-repository)

- You need a valid [https://github.com/settings/tokens](Github token)
  - Choose Classic token with `public_repo` only
  - Keep the generated token (will not be accessible again)

- Run `opam publish` to install the opam-publish plug-in
- Run `opam publish https://git.frama-c.com/pub/why3find/-/archive/$version/why3find-$version.tar.gz`, that is the link generated by the Gitlab release.
- Check and validate the informations presented by opam publish.

- Watch over the opam-repository CI and get the PR merged.
